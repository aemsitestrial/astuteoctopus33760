# XE Footer V2

The **XE Footer V2** is the Xcel footer rendered with the `@ignite/web` footer
composition, following its reference markup:

```html
<xe-footer columns="5">
  <span slot="copyright">© 2026 Xcel Energy Inc. All rights reserved.</span>
  <xe-footer-column heading="Company">
    <xe-hyperlink href="…" variant="variant">Careers</xe-hyperlink>
    …
  </xe-footer-column>
  …
  <xe-icon-button slot="social" size="xl" href="…" aria-label="Facebook (opens in a new window)">
    <xe-icon icon="faSquareFacebook"></xe-icon>
  </xe-icon-button>
  …
  <xe-hyperlink slot="legal" href="…" variant="variant" trailing-icon>Privacy</xe-hyperlink>
  …
  <img slot="banner-image" src="…" alt="">
</xe-footer>
```

The logo (Ignite's built-in Xcel Energy logo when none is authored) and the
banner tagline render too. Below 1024px each link column collapses into an
accordion (`<xe-accordion>`). Colors, spacing and typography come from the
Ignite design tokens (`scripts/ignite/bundle/themes/tokens.css`), loaded by
`scripts/components/ignite.js`.

## Authoring model

The block is a **container** (its `xe-footer-v2` filter): its own fields
render as rows first, then one row per child item. The controls below map
one-to-one to the model (`blocks/xe-footer-v2/_xe-footer-v2.json`).

    <tr><th>Field</th><th>Model type</th><th>Purpose</th></tr>
  </thead>

### Child items: social and legal links

<table>
  <thead>
    <tr><th>Item</th><th>Field</th><th>Renders as</th></tr>
  </thead>
  <tbody>
    <tr><td>XE Footer Social Links</td><td><code>socialLinks</code> (multi: <code>cta_link</code> profile URL + <code>cta_linkText</code> network select)</td><td>Social icon buttons (Facebook, X, Instagram, LinkedIn, YouTube), opening in a new window</td></tr>
    <tr><td>XE Footer Legal Links</td><td><code>legalLinks</code> (multi: <code>cta_link</code> + <code>cta_linkText</code>)</td><td>Legal links with a trailing icon</td></tr>
  </tbody>
</table>

Each item is decorated by its own block — `blocks/xe-footer-social-links` and
`blocks/xe-footer-legal-links` export `decorate(item)`, returning the elements
the footer slots in, and `decorateDefaults()`, the live Xcel Energy footer's
links used when no item is authored.

In the Universal Editor each item row carries its model (`data-aue-model`), so
it lands in the right place regardless of its links, and its instrumentation
moves onto the first button or link rendered from it, keeping every item in the
editor's content tree. An item with no links yet shows an "Add social links" /
"Add legal links" placeholder (editor only) so it can be selected and filled in.
On published pages rows carry no model, so a list whose links all point to
social networks is the social item and any other list of links is the legal
item.

### Footers authored with earlier models

Rows are recognized by what they hold, not by position, so earlier footers keep
rendering: footers created while the block was **key-value** (`name | value`
rows, including their five link-column slots and rich-text social / legal
fields), and the original **positional** layout (rich-text social, legal and
footer links). The current model has no link-column fields, so link columns
render only from those earlier footers.

## Testing

- **Interaction tests** — each story's `play` function asserts the rendered
  Ignite structure. Run headless with `npm run test:storybook`.
- **Visual tests** — Chromatic snapshots each story and flags pixel diffs.
- **Accessibility** — the a11y panel runs axe checks on every story, enforcing
