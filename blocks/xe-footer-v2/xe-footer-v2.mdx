# XE Footer V2

The **XE Footer V2** is the Xcel footer rendered with the `@ignite/web` footer
composition, following its reference markup:

```html
<xe-footer columns="5">
  <span slot="copyright">© 2026 Xcel Energy Inc. All rights reserved.</span>
  <xe-footer-column heading="Company">
    <xe-hyperlink href="…" variant="variant">Careers</xe-hyperlink>
    …
  </xe-footer-column>
  …
  <xe-icon-button slot="social" size="xl" href="…" aria-label="Facebook (opens in a new window)">
    <xe-icon icon="faSquareFacebook"></xe-icon>
  </xe-icon-button>
  …
  <xe-hyperlink slot="legal" href="…" variant="variant" trailing-icon>Privacy</xe-hyperlink>
  …
  <img slot="banner-image" src="…" alt="">
</xe-footer>
```

Up to five link columns render, plus the logo (Ignite's built-in Xcel Energy
logo when none is authored) and the banner tagline. Social buttons open the
profile in a new window.

Below 1024px each link column collapses into an accordion (`<xe-accordion>`).
Colors, spacing and typography come from the Ignite design tokens
(`scripts/ignite/bundle/themes/tokens.css`), loaded by
`scripts/components/ignite.js`.

## Authoring model

The controls below map one-to-one to the block's authoring model
(`blocks/xe-footer-v2/_xe-footer-v2.json`), so this page mirrors what an author edits
in the Universal Editor.

The block is a **key-value block** (`"key-value": true` on its template): every
field renders as a `name | value` row, and the decorator reads each field by
name. A blank field is simply absent, so it can't shift the fields after it.
Link columns are five fixed slots; a slot renders only when it has links.

### Child items: social and legal links

The block is also a container for two items (its `xe-footer-v2` filter):

<table>
  <thead>
    <tr><th>Item</th><th>Field</th><th>Purpose</th></tr>
  </thead>
  <tbody>
    <tr><td>XE Footer Social Links</td><td><code>socialLinks</code> (multi: <code>cta_link</code> profile URL + <code>cta_linkText</code> network select)</td><td>Social icon links (Facebook, X, Instagram, LinkedIn, YouTube), opening in a new window</td></tr>
    <tr><td>XE Footer Legal Links</td><td><code>legalLinks</code> (multi: <code>cta_link</code> + <code>cta_linkText</code>)</td><td>Legal text links</td></tr>
  </tbody>
</table>

Each item renders as a list of links. Published markup doesn't record which
item a list came from, so a list whose links all point to known social
networks is the social list and any other list is the legal list; if AEM
renders the items as key-value rows, their field names identify them.

When neither an item nor the older `social` / `legal` rich-text field is
authored, the live Xcel Energy footer's links render as defaults: the five
social profiles, and Online Terms of Use, Privacy and Accessibility.

Footers created before the key-value model render as positional rows with a
single `footerlinks` rich-text field (heading + link-list pairs). The block
still reads those, so existing content keeps working; they only need
re-authoring into the column slots to be edited with the new fields.

## How it renders

The block's decorator reads each authored field by its key, builds
the Ignite markup, and waits for the footer bundle
(`scripts/ignite/bundle/compositions/footer/xe-footer.js`) to register its
elements. Stories run that real `decorate()` against the shipped
`xe-footer-v2.css` and the same bundle, so what you see here matches production.

## Testing

- **Interaction tests** — each story's `play` function asserts the decorated
  Ignite structure (columns, links, logo, banner tagline). Run headless with
  `npm run test:storybook`.
- **Visual tests** — Chromatic snapshots each story and flags pixel diffs.
- **Accessibility** — the a11y panel runs axe checks on every story, enforcing
  WCAG 2.2 AA conformance.
