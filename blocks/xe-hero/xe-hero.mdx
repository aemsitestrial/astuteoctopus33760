# XE Hero

A full-bleed hero with a background image behind a scrim, a title, an optional
subtitle, and up to two positional CTAs. The block rebuilds the authored content
into web-component markup — `<xe-hero>` with slotted media/title/subtitle/actions
and `<xe-button>` CTAs — defining those custom elements on first run.

## Authoring model

The controls below map one-to-one to the block's authoring model

primary (filled) button; the second is the secondary (outline) button.

## How it renders

The decorator classifies the authored rows positionally — the image row (has an
`img`), CTA rows (have links), and the remaining text rows in document order
(title, then subtitle) — and rebuilds them into the web-component markup above.
The two custom elements (`xe-hero`, `xe-button`) are small shadow-DOM components
defined by the block on first run: the media renders full-bleed behind a scrim,
and the title, subtitle, and actions are distributed through named slots. Six
locked variants set height and text alignment; the base variant uses the
responsive default. Stories run that real `decorate()` against the shipped CSS,
so what you see here matches production.

## Testing

- **Interaction tests** — each story's `play` function asserts the decorated
  structure (slotted title/subtitle/media, CTA buttons, variant attributes) and
  waits for the custom elements to upgrade. Run headless with
  `npm run test:storybook`.
- **Visual tests** — Chromatic snapshots each story and flags pixel diffs.
- **Accessibility** — the a11y panel runs axe checks on every story, enforcing
  WCAG 2.2 AA conformance.
